# Анонсы релизов в Discord

При публикации GitHub Release workflow отправляет пост в канал `#announcements` через webhook. Событие `edited` специально не обрабатывается, чтобы не плодить дубликаты.

## 1. Создать webhook в Discord

1. Откройте сервер Discord → канал `#announcements`.
2. Настройки канала → **Integrations** (Интеграции) → **Webhooks**.
3. **New Webhook** / **Создать вебхук**.
4. Имя можно оставить любым (скрипт всё равно подставит «Aeronautics Sky Islands» в поле content).
5. Убедитесь, что webhook привязан к `#announcements`.
6. **Copy Webhook URL** и сохраните ссылку. Это секрет: не коммитьте его в репозиторий и не публикуйте в чатах.

Формат URL: `https://discord.com/api/webhooks/<id>/<token>`.

## 2. Добавить секрет в GitHub

1. Репозиторий → **Settings** → **Secrets and variables** → **Actions**.
2. **New repository secret**.
3. Name: `DISCORD_WEBHOOK_URL`
4. Secret: вставьте URL webhook.
5. Save.

Права workflow: только `contents: read` (чтение релизов и ассетов). Отдельный Personal Access Token не нужен.

## 3. Что уходит в Discord

Каждый релиз — одно или несколько сообщений:

- заголовок (имя релиза) и тег;
- дата публикации;
- ссылка на GitHub Release (кликабельный заголовок и строка в тексте);
- текст notes: заголовки становятся **жирными**, списки и ссылки сохраняются, картинки из тела (`![]()` и `<img>`) вынимаются и показываются отдельно;
- изображения из notes и image-ассеты релиза — как картинка эмбеда;
- `.mrpack` / `.zip` и прочие не-картинки — списком ссылок на скачивание.

Лимиты Discord соблюдаются автоматически (описание эмбеда ≤ 4096 символов, ≤ 10 эмбедов в сообщении, ≤ 6000 символов суммарно). Длинные notes обрезаются или делятся на несколько сообщений, в конце остаётся ссылка «полный текст релиза».

### Картинки и видимость репозитория

| Ситуация | Как показывается |
| --- | --- |
| Публичный репозиторий, обычный HTTPS URL картинки | URL в эмбеде (Discord сам скачивает) |
| Публичный репозиторий, `github.com/user-attachments/assets/...` | Тоже URL в эмбеде: GET без авторизации проходит |
| Приватный репозиторий, user-attachments или ассеты GitHub | Скрипт скачивает файл с `GITHUB_TOKEN` и заливает вложением (`attachment://…`), чтобы crawler Discord не упёрся в 401/403 |
| Картинка больше ~8 МБ | Вложение не отправится; останется ссылка в тексте |

Подписанные S3-URL (они живут ~5 минут) скрипт не кладёт в эмбед — их Discord может не успеть забрать.

## 4. Проверка backfill (сначала dry-run)

Workflow можно запустить вручную: **Actions** → **Discord release announcement** → **Run workflow**.

Рекомендуемый порядок:

1. Убедитесь, что секрет `DISCORD_WEBHOOK_URL` уже добавлен.
2. **Run workflow**, поле **tag** оставьте пустым, **dry_run = true** (так по умолчанию).
3. Откройте лог шага *Post release(s) to Discord* и проверьте, как выглядят посты. В Discord ничего не уйдёт.
4. Для одного релиза: **Run workflow**, укажите тег как на GitHub (`v0.3.0`, `v.0.4.0` или `Beta`), **dry_run = true**, затем при необходимости повторите с **dry_run = false**.
5. Чтобы выгрузить **все** существующие релизы в канал (от старых к новым, с паузой 3 секунды): **tag** пустой, **dry_run = false**.

`dry_run = false` без тега отправит все релизы подряд. Для первого живого теста лучше указать один тег.

Локально (ничего не постит):

```bash
python .github/scripts/discord_release.py --mode backfill --dry-run --repo Poligorn/Aeronautics-SkyIslands-Modpack
python .github/scripts/discord_release.py --mode backfill --dry-run --tag v0.3.0
```

Нужен `GITHUB_TOKEN` или `gh auth` только если API без токена начнёт упираться в лимиты. В Actions токен выдаётся сам.

Тесты без сети:

```bash
python -m unittest discover -s .github/scripts -p "test_*.py" -v
```

## 5. Ограничения

- Редактирование уже опубликованного релиза **не** создаёт новый пост. Если нужно перепостить — запустите workflow вручную с этим тегом.
- Черновики (`draft`) пропускаются.
- Pre-release публикуются, в заголовке будет пометка `(pre-release)`.
- Discord может не отрисовать редкий URL картинки; для приватных репозиториев как раз включена загрузка вложением.
- Webhook должен иметь право писать в `#announcements`. Если канал только для новостей, пост появится там как обычное сообщение webhook-бота.
